| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F  | Функциональные (Functionality) | |
| F1 | Клиент видит на сайте список доступных депозитов с актуальными ставками | |
| F2 | Клиент может подать заявку на депозит через сайт (ФИО + номер телефона) | |
| F3 | Заявка на депозит через сайт попадает на обработку менеджеру кол-центра, менеджер может предложить особые условия | |
| F4 | Клиент может подать заявку на депозит через интернет-банк (выбор счёта, суммы, подтверждение SMS) | |
| F5 | В интернет-банке клиент видит список доступных депозитов с актуальными ставками и персонализированные ставки лично для него | |
| F6 | Сотрудник отделения может подавать заявки на депозит напрямую в АБС | |
| F7 | Заявки на открытие депозитов через интернет-банк подтверждает менеджер бэк-офиса в АБС (на этапе MVP) | |
| F8 | Клиент получает SMS-уведомления о подтверждении ставки и открытии депозита через интернет-банк | |
| U  | Удобство использования (Usability) | |
| U1 | Интерфейс работы должен быть максимально удобным для клиента                                | |
| U2 | Интерфейс должен учитывать корпоративную систему дизайна, использовать корпоративные цвета и брендированные элементы | |
| R  | Надёжность (Reliability) | |
| R1 | Все сервисы должны работать 24/7 и быть доступны в 99,9% случаев | |
| R2 | Система должна обеспечивать автоматическое переключение на резервный ЦОД при сбое основного | |
| R3 | Интернет-банк должен выдерживать 100% нагрузку при работе через резервный ЦОД | |
| P  | Производительность (Performance) | |
| P1 | Отклик по всем операциям должен быть максимально быстрым и занимать миллисекунды | |
| P2 | Система должна поддерживать горизонтальное масштабирование с распределением нагрузки между двумя ЦОД | |
| S  | Поддерживаемость (Supportability) | |
| S1 | Разработка документации для дальнейшего расширения системы | |
| S2 | Использование существующих технологий, либо совместимых с существующими | |
| +R | + Ограничения (Restrictions) |  |
| +R1 | Шифрование трафика между сайтом и клиентом | |
| +R2 | Шифрование данных при передаче между интернет-банком и АБС | |
| +R3 | Выделить открытие депозитов в отдельный микросервис | Переход на микросервисную архитектуру в долгосрочной перспективе. Для MVP вынесем работу с депозитами в отдельный микросервис |
| +R4 | Использовать Kafka для очереди сообщений | Kafka поможет разгрузить АБС, но потребует промежуточного слоя (REST) из-за несовместимости текущего интернет-банка |
| +R5 | Ставки по депозитам должны храниться централизованно | Перенесём хранение ставок в БД микросервиса для работы с депозитами, это ускорит работу с клиентом и упростит работу бэк-офис менеджерам, а так же исключит возможные ошибки |
